# S02-ID-01 — authoritative critical-event registration identity

**Owner-approved contract, 16 November 2026.** Authority: the project owner's current instruction to close S02-ID-01 and begin bounded Sprint 03. This closes the design dependency; it does not certify an implemented mTLS registry, live enrollment, HA or independent security/legal approval.

## Canonical mapping

| Wire/contract identity | Authoritative server object |
|---|---|
| tenant_id | Organization.id (customer boundary); no client-selected MSP/customer inference |
| source_id | Stable DataSource.id; names/hostnames/endpoints are not identity |
| collector_id | ManagedAgent.id, the registered installation identity |
| configuration_collector_id | Collector.id; configuration identity is distinct from installation identity |
| principal/generation | Authenticated per-install certificate principal + current registry generation; never forwarded client headers |
| environment | Server-resolved source/resource environment, validated against the registered binding |

The server resolves the complete Organization → DataSource → Collector → ManagedAgent registration on every request under a consistent locked authority snapshot. Every object must exist and remain enabled; source owner, Collector source and installation Collector must agree. Revocation, expiry, deletion, reassignment, stale generation and missing/changed capability deny new admission. A payload tenant/source/Collector ID is only a value to compare. No payload, cached scope, display label or unsigned forwarded header grants authority. Runtime transport adapters must perform real certificate authentication and current registry reads; the policy module is not that adapter.

An installation owns only explicitly registered sources and capabilities. `critical-event:submit` permits new event submission; historical replacement recovery requires separately granted `recover:source-events`. It is never inferred from ordinary submission, a revoked identity or knowledge of an old event ID. Reassignment does not rewrite historical ownership: create/approve a new binding/identity where appropriate; preserve the old event ledger and receipt provenance. One fenced current owner per canonical collection unit is required before production operation.

Stable logical event key: `(tenant_id, source_id, event_id)`; collector replacement does not create a new logical event. Retries preserve event_id, canonical bytes/digest, schema_version and canonicalization_version. Any equal-key differing digest/version is an integrity conflict, not an update. Original failure and later retry/recovery remain distinct source-native events. Event IDs are opaque nonempty strings, not UI row names; payload SHA-256 is exactly 32 bytes.

## Executable negative contracts

`backend/app/critical_events/identity.py` exposes a fail-closed policy over immutable server-resolved snapshots. Unit tests cover forged tenant/source/install IDs, missing/deleted/disabled parents, reassignment, unverified mTLS, stale generation, forged principal, capability/environment mismatch, ungranted historical recovery and retry digest/version conflicts. No public route or legacy agent authentication is changed by this contract PR. Actual transport integration and real database concurrency/revocation tests remain separate Sprint 03 acceptance.
